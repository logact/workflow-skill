# 任务票据增加优先级与前置依赖，新增守护调度器自动执行

## 决策内容

1. 任务 frontmatter 增加两个字段：`priority: 高|中|低`（默认中）、`depends_on:`（逗号分隔的任务 ID，空 = 无前置）；`wf-new.sh task` 增加 `--priority`、`--depends-on` 参数
2. 新增 `scripts/wf-daemon.sh` 守护调度器，子命令 `once / start [--interval N] / stop / status`：
   - 派发：从"待办且 depends_on 全部完成"的任务里，按优先级（高>中>低，同级按 ID 升序）每趟取一个，`wf-status 进行中` 后用 `orca worktree create --agent $WF_DAEMON_AGENT --prompt <任务简报>` 派发到独立 worktree（遵循 D-0002），把 worktree id 和分支写回任务 frontmatter
   - 收口：每趟检查进行中任务的分支是否已合并回主分支（`git merge-base --is-ancestor`），合并了 → 转"待验收"交用户验收（合并成功 = 结果层面通过，见 D-0002）
3. worktree 里的执行 agent 只做代码工作；所有记录操作（wf-status、日志）一律对主 checkout 的 docs/ 执行（`WF_DOCS=<主checkout>/docs`），docs/ 的唯一事实源留在主 checkout

## 背景与理由

1. 自动化执行必须有执行顺序依据：优先级表达"哪个重要"，depends_on 表达"哪个必须先做完"，两者都是调度器的输入
2. 派发做"每趟只取一个"而非一次全派：优先级排序才真正生效，且循环执行下后续 pass 会自然带出并行（worktree 隔离已保证互不污染）
3. 选 Orca worktree + agent 派发（放弃 daemon 自己干活）：复用 D-0002 的隔离与合并判据，daemon 只是调度器不含业务逻辑
4. 记录留在主 checkout：worktree 是临时执行环境，里面的 docs/ 会随分支合并产生冲突；事实源唯一才不会乱

## 影响范围

- assets/templates/tasks/_template.md、scripts/wf-new.sh：新字段与参数
- scripts/wf-check.sh：priority 枚举校验
- scripts/wf-daemon.sh：新脚本
- SKILL.md、assets/README.md：调度器机制与命令表
