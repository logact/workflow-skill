# 新增起草状态：任务创建后须经用户审批才进入待办

## 决策内容

状态机最前端增加"起草"状态：任务创建时进入"起草"，用户审批通过后 `wf-status.sh T-xxxx 待办` 才进入可执行队列。状态机变为：

```
起草 → 待办 → 进行中 → 待验收 → 完成
```

起草是可执行队列的闸门：守护调度器（D-0005）只派发"待办"任务，起草中的任务永远不会被自动执行。仅任务类型适用（决策创建即完成、backlog 创建即已搁置、issue 保持待办不变）。

## 背景与理由

1. 守护调度器会自动执行待办任务，没有审批门就意味着"agent 随手建的任务会被自动跑掉"——执行资源花在哪必须经用户点头
2. 起草放在待办之前而不是用 backlog 代替：backlog 是"以后再说"，起草是"马上要进队列、只差审批"，语义不同
3. 只约束任务类型：issue 不会被调度器自动执行，无需多一道审批

## 影响范围

- scripts/wf-common.sh：合法状态集合加"起草"
- scripts/wf-status.sh：新增流转 起草→待办 / 起草→已搁置 / 起草→已废弃
- scripts/wf-new.sh：任务默认状态改为"起草"
- docs/PRD.md、SKILL.md、assets/README.md：状态机与审批门说明
