# 归档机制与 ID 引用约定

## 决策内容
1. 终态文件归档到各类型目录下的 `_archive/YYYY-MM/`，每轮验收后执行；活跃文件、未被取代的决策、INDEX/README/PRD 永不归档。
2. 文件间引用一律使用全局唯一 ID（形如 `I-xxxx`，四位数字编号），不写相对路径。

## 背景与理由
问题：domain/ 下文件持续累积，活跃文件会被大量已完成文件淹没，无法看。

- 选 `_archive/YYYY-MM` 分散在各类型目录内，放弃集中式顶层 archive 目录：归档后仍保留"类型划分"（PRD 原则3），且找某类型的历史不用跨目录。
- 必须配 ID 引用约定：归档本质是移动文件，而之前（见 docs/logs/2026-11-18 第一轮决策）正是为了不断链才放弃状态子目录。ID 全局唯一、与路径无关，移动后引用依然有效，定位改用 grep ID，彻底解决矛盾。
- 归档时机挂在"每轮验收后"而非定时：复用既有机制6的扫描节奏，不引入新流程。

## 影响范围
- docs/README.md：新增"归档机制"一节，追溯链规则改为 ID 引用
- docs/{tasks,issues,backlog}/_template.md：source 与处理记录改用 ID 写法
- 后续所有新文件遵循 ID 引用；历史文件（目前无）不涉及迁移
