# 新增 /orch 命令：调度长官模式，统一接管任务与 issue 创建、审批流转与队列监控

## 决策内容

新增 `/orch` 斜杠命令：激活后当前 agent 成为本项目的"调度长官"——

1. 上岗：确认 docs/ 结构存在（否则 wf-init）、启动 wf-daemon 守护线程、向用户汇报当前盘面（起草/待办/进行中/暂停/待验收各多少）
2. 唯一入口：所有任务创建（带 priority/depends_on）和 issue 创建都经过调度长官；任务创建即起草，调度长官向用户复述目标与验收标准，用户批准才转待办（D-0006）
3. 队列管理：调整优先级/依赖、监控暂停与待验收任务并报告用户裁决（恢复/重新排队/废弃；验收通过/打回）
4. 不亲自写代码：执行由守护线程派发到 Orca worktree 的执行 agent（D-0002/D-0005）
5. 下岗：用户说退出调度时 wf-daemon stop 并汇报最终盘面（在跑的 worktree 不受影响）

实现：`orch/SKILL.md` 作为本 skill 的子技能（name: orch），同时在用户技能目录建符号链接注册为顶层技能，使命令正好是 `/orch`（否则只能 `/workflow.orch`）。

## 背景与理由

1. 自动化程度提高后（守护派发、合并收口、暂停检测）需要一个"人在环路的总控"：用户面对的是一个能对话的调度长官，而不是一堆零散的 wf- 命令——这贴合 PRD 原则2（最小摩擦）
2. 任务与 issue 创建收敛到单一入口，防止多路创建绕过起草审批门（D-0006）
3. 调度长官只做调度不写代码：调度与执行职责分离，执行继续在 worktree 隔离环境里跑（D-0002），出了状况影响面可控
4. 用符号链接注册顶层技能而不是把 orch 移出仓库：内容留在 workflow-skill 仓库里版本管理，一处事实源

## 影响范围

- orch/SKILL.md：新增子技能文件
- ~/.agents/skills/orch：指向本仓库 orch/ 的符号链接（部署动作，非仓库内容）
- SKILL.md：补充 /orch 命令说明
- scripts/wf-new.sh：顺带修复标题含 "/" 时创建文件失败的 bug（文件名用 fname 变量，斜杠替换为 -）
